1. Purpose and scope

This SOP explains, step by step, how to set up an AI chatbot that answers questions and produces reports from a MySQL database, through Telegram and a web link. It records exactly what was done for the first bot (ReportBot on the venuserp_replica database) so that the same procedure can be repeated to create more bots for other databases or departments.

Users can chat in English, Hindi, Gujarati or Marathi. Managers can teach the bot company report formats with rules and cross-checks, which then become /commands (for example /daily_dispatch). Every report is saved to history.

Important: This document uses placeholders such as <YOUR_CLAUDE_KEY> and <BOT_DB_PASSWORD>. Never write real passwords, API keys or bot tokens into this SOP or share them in chat.

2. How the system works

PartWhat it does
Telegram botStaff chat with the bot on mobile; receive tables, Excel, PDF and charts.
Web chat linkSame bot in any browser, for people without Telegram. Each person gets a personal link.
ReportBot server (Docker)Runs on the laptop/server. Talks to Claude, MySQL and Telegram.
Claude (Anthropic API)Understands the question, writes safe SQL, follows report rules, writes summaries.
MySQL – ERP databaseYour business data (e.g. venuserp_replica). Read-only access.
MySQL – bot databaseBot's own data: users, roles, taught reports, history, schedules (database 'reportbot').
Cloudflare tunnelGives the laptop a public https link so Telegram and outside users can reach it.

Flow: User message → Telegram / web → ReportBot → Claude decides what data is needed → read-only SQL on MySQL → report rendered (table / Excel / PDF / chart / HTML) → sent back and saved in history.

4. Step-by-step setup

Step 1 – Get the keys

  1. Create the Claude API key at console.anthropic.com → API Keys. Copy it once; it is shown only one time. It must start with sk-ant-api03-.
  2. In Telegram open @BotFather, send /newbot, give a display name and a username ending in _bot (e.g. venuserp_bot). Copy the token.
  3. In Telegram open @userinfobot and press Start. Note your numeric ID.

Step 2 – Prepare MySQL (run in MySQL Workbench as admin)

Create the bot's own database and a dedicated user. The user can only READ the ERP database and has full access only to the bot database. Use letters and numbers only in the password (symbols like @ # break the connection line).

CREATE DATABASE IF NOT EXISTS reportbot CHARACTER SET utf8mb4;

CREATE USER 'reportbot'@'%'         IDENTIFIED BY '<BOT_DB_PASSWORD>';
CREATE USER 'reportbot'@'localhost' IDENTIFIED BY '<BOT_DB_PASSWORD>';

GRANT SELECT ON <ERP_DB_NAME>.* TO 'reportbot'@'%';
GRANT SELECT ON <ERP_DB_NAME>.* TO 'reportbot'@'localhost';
GRANT ALL    ON reportbot.*     TO 'reportbot'@'%';
GRANT ALL    ON reportbot.*     TO 'reportbot'@'localhost';

FLUSH PRIVILEGES;
Note: Why both '%' and 'localhost': from Docker Desktop, MySQL on the same laptop sees the connection as 'localhost'. Using root failed with 'Access denied for user root@localhost', so always use this dedicated user.

Step 3 – Install Docker Desktop

  1. Download and run the Docker Desktop installer (keep 'Use WSL 2').
  2. Restart the laptop.
  3. Open Docker Desktop, accept terms (sign-in can be skipped) and wait for 'Engine running' (green, bottom-left).
  4. If it asks to update WSL: open PowerShell as Administrator, run wsl --update , then reopen Docker Desktop.

Make the docker command available in every PowerShell window. Docker was installed per-user, so Windows could not find it ('docker is not recognized'). Find docker.exe:

Get-ChildItem -Path "C:\Program Files","C:\ProgramData","$env:LOCALAPPDATA" -Filter docker.exe -Recurse -ErrorAction SilentlyContinue | Select-Object FullName

On our laptop it was C:\Users\User\AppData\Local\Programs\DockerDesktop\resources\bin\docker.exe. Add its folder to Path permanently (one time), then close and reopen PowerShell:

[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";C:\Users\User\AppData\Local\Programs\DockerDesktop\resources\bin", "User")

Check:

docker --version

Step 4 – Put the project files in place

  1. Right-click reportbot.zip → Extract All → to C:\ (result: C:\reportbot containing app, docker-compose.yml, README.md).
  2. Move cloudflared.exe into C:\reportbot.
  3. Open PowerShell and go to the folder:
cd C:\reportbot
dir
copy .env.example .env
notepad .env

Step 5 – Fill in the .env settings file

Replace the whole content of .env with the template below and fill in the <…> values. No spaces around '='. Save with Ctrl+S.

# ---------- Claude ----------
ANTHROPIC_API_KEY=<YOUR_CLAUDE_KEY>
CLAUDE_MODEL=claude-sonnet-5-5

# ---------- ERP database (read-only) ----------

# ---------- Bot storage ----------
BOT_DB_URL=mysql+pymysql://reportbot:<BOT_DB_PASSWORD>@host.docker.internal:3306/reportbot?charset=utf8mb4

# ---------- Telegram ----------
TELEGRAM_BOT_TOKEN=<BOTFATHER_TOKEN>
TELEGRAM_MODE=direct
TELEGRAM_WEBHOOK_SECRET=<ANY_RANDOM_TEXT>

# ---------- Web ----------

SERVICE_API_KEY=<ANY_RANDOM_TEXT_2>
BOOTSTRAP_ADMIN_NAME=admin
BOOTSTRAP_ADMIN_TELEGRAM_ID=<YOUR_NUMERIC_TELEGRAM_ID>
BOOTSTRAP_ADMIN_WEB_TOKEN=<ADMIN_WEB_PASSWORD>

# ---------- Limits ----------

ANTHROPIC_API_KEYMust start with sk-ant-api03-. A key starting sk-ant-usr- will not work.

Step 6 – Build and start the bot

Docker Desktop must show 'Engine running'. First build takes about 5–10 minutes.

cd C:\reportbot
docker compose up -d --build

Wait 20–30 seconds, then check that it started:

docker compose ps
docker compose logs --tail 30 reportbot
  • Good: STATUS shows 'Up' and logs show 'Application startup complete'.
  • Bad: STATUS 'Restarting' → read the last log lines and use the Troubleshooting table (section 8).

Create the admin and print the admin web link:

docker compose exec reportbot python -m tools.manage init

Open http://localhost:8000/?token=<ADMIN_WEB_PASSWORD> in Chrome and type 'show me all tables' as a first test.

Note: The admin is created on the very first start. If the Telegram ID in .env was wrong or empty at that moment, fix it in MySQL: UPDATE reportbot.rb_users SET telegram_id = '<YOUR_ID>' WHERE id = 1;

Step 7 – Public link and Telegram

Open a SECOND PowerShell window and keep it open the whole time the bot is used:

cd C:\reportbot
.\cloudflared.exe tunnel --url http://localhost:8000

Copy the link it prints, e.g. https://abc-xyz-123.trycloudflare.com. Test it in Chrome: <link>/health must show {"ok":true} (a new link can take up to a minute).

In the first PowerShell window set the link and restart:

notepad .env          # set PUBLIC_BASE_URL=https://abc-xyz-123.trycloudflare.com  (no / at end)
docker compose up -d --force-recreate
docker compose exec reportbot python -m tools.manage set-webhook

set-webhook must print 'ok': True. Then in Telegram open the bot (t.me/<bot_username>), press Start, and try /myid and 'show me all tables'.

5.3 SQL (MySQL Workbench)

-- see users and their tokens
SELECT id, name, role, telegram_id, active, web_token FROM reportbot.rb_users;

-- remove access (history is kept)
UPDATE reportbot.rb_users SET active = 0 WHERE id = 2;
-- give access back
UPDATE reportbot.rb_users SET active = 1 WHERE id = 2;
-- change role
UPDATE reportbot.rb_users SET role = 'manager' WHERE name = 'Kunal';
-- add Telegram ID later
UPDATE reportbot.rb_users SET telegram_id = '123456789' WHERE name = 'KK';
-- new link for someone (old link stops working)
UPDATE reportbot.rb_users SET web_token = '<NEW_SECRET_TEXT>' WHERE id = 2;

A person's web link = <current PUBLIC_BASE_URL>/?token=<their web_token>. Never deactivate id 1 (main admin).

Print one person's full link from PowerShell:

docker compose exec reportbot python -c "from app import store, config; u=[x for x in store.list_users() if x['name']=='Dwarika Gupta'][0]; print(config.PUBLIC_BASE_URL + '/?token=' + u['web_token'])"

6. Teaching reports (rules, format, cross-checks)

  1. In Telegram or web chat send /teach followed by a full description (template below). Attaching an existing Excel/PDF report with caption 'is format me banao' makes the bot copy that layout.
  2. Answer the bot's questions (which date column, which status means cancelled, etc.).
  3. Check the preview against a manual report for 2–3 past dates that are known to be correct. Correct it until numbers match.
  4. Say 'save'. The bot replies with the new command, e.g. /daily_dispatch.
  5. To change later: /teach daily_dispatch and describe the change (old versions are kept).
/teach
Report name: daily_dispatch
Purpose: Daily dispatch report for management

FORMAT (follow exactly):
- Columns: Branch | Challan Count | Qty (MT) | Amount (₹)
- Sort by Amount, highest first; TOTAL row at the bottom
- Excel + PDF, bar chart of Amount by Branch
- Summary in Hindi, 3 lines

RULES:
1. Use challan_date, not order date
2. Exclude cancelled challans (status = 'C')
3. Exclude stock-transfer challans
4. Amount without GST, rounded to 2 decimals
5. Default period: yesterday

CROSS-CHECKS (run every time, before giving the report):
1. Report TOTAL Qty must equal total qty from the dispatch table for the same period
2. Challan count must match count of distinct challan numbers
3. No branch should be blank or "Unknown"
4. If any check fails, show ⚠️ with the difference
5. End with a "✅ Checks passed" line listing each check
UsageResult
/daily_dispatchYesterday's report with saved rules
/daily_dispatch Pune 1-15 Oct excelSame format, other filter / format
/skillsList of taught reports
/historyRecent reports (re-send: 'report #12 pdf me bhejo')
roj subah 9 baje /daily_dispatch is group me bhejoCreates a scheduled report (manager/admin)
/schedulesList scheduled reports
/newStart a fresh conversation
Note: Cross-checks written in the rules are followed by the AI every run. For hard-coded checks that block a report on mismatch, a code update ('Checks' section per report) is required.

7. Daily operation (laptop setup)

The bot works only while the laptop is on, Docker Desktop is running and the cloudflared window is open. After every restart of the laptop:

  1. Open Docker Desktop and wait for 'Engine running' (the bot container starts by itself).
  2. PowerShell window 2: cd C:\reportbot then .\cloudflared.exe tunnel --url http://localhost:8000 → copy the NEW link.
  3. PowerShell window 1: notepad .env → update PUBLIC_BASE_URL → save.
  4. docker compose up -d --force-recreate
  5. docker compose exec reportbot python -m tools.manage set-webhook (must show ok: True)
  6. Send users their link again with the new address (their token does not change).
Useful commandPurpose
docker compose psIs the bot Up or Restarting?
docker compose logs --tail 30 reportbotSee recent errors
docker compose logs -f reportbotWatch live (Ctrl+C to stop)

docker compose up -d --buildApply code changes (rebuild)
docker compose downStop the bot

9. Security rules

  • Never paste the Claude key, Telegram token or passwords into chat, email or this SOP. If exposed: Telegram → @BotFather /revoke; Claude → delete and create a new key.
  • Always connect with the dedicated read-only bot user, never with root.
  • Prefer a replica database for the ERP data.
  • Give admin only to fully trusted people; use viewer for most staff.
  • Each web link is personal. If a link is forwarded, issue a new web_token.
  • Deactivate users who leave the company (active = 0).
  • Report files are stored on the bot server; clean old files periodically if they are sensitive.

10. Reusing this SOP to create another bot

Each bot is a separate copy of the project with its own Telegram bot, its own bot database, its own port and its own tunnel. Docker keeps them apart automatically because the folder names differ.

ItemBot 1 (done)New bot (example)
FolderC:\reportbotC:\hrbot
Telegram bot@venuserp_botNew one from @BotFather, e.g. @venushr_bot
ERP databasevenuserp_replicae.g. hrms_replica
Bot databasereportbothrbot (new CREATE DATABASE + GRANT)
Port80008001
Tunnel--url http://localhost:8000--url http://localhost:8001
  1. Extract reportbot.zip again into a new folder, e.g. C:\hrbot, and copy cloudflared.exe into it.
  2. Create a new Telegram bot in @BotFather.
  3. In MySQL: CREATE DATABASE hrbot …; GRANT SELECT on the new ERP database and ALL on hrbot to the bot user (Step 2 SQL with new names).
  4. Edit docker-compose.yml: change ports: ["8000:8000"] to ports: ["8001:8000"].
  5. Create .env (Step 5) with the new Telegram token, new database names and a new COMPANY_NAME/admin password.
  6. cd C:\hrbot → docker compose up -d --build → docker compose exec reportbot python -m tools.manage init
  7. New tunnel window: .\cloudflared.exe tunnel --url http://localhost:8001 → set PUBLIC_BASE_URL → --force-recreate → set-webhook.
  8. Add users and teach reports for the new bot (sections 5 and 6).
Note: Run every docker compose command from inside that bot's own folder; the command acts on the bot in the current folder.

11. Moving to a permanent setup (recommended for company use)

  • Run the bot on an always-on machine (office server or cloud VM) instead of a laptop.
  • Use a named Cloudflare tunnel on the company domain (e.g. reports.venuspipes.com) so the link never changes.
  • Copy the project folder and .env as-is; set PUBLIC_BASE_URL to the permanent address; run set-webhook once.
  • After that, users' links and Telegram keep working through restarts.
